Task Statement 5.5 — Design human review workflows and confidence calibration

Knowledge of:

  • The risk that aggregate accuracy metrics (e.g., 97% overall) may mask poor performance on specific document types or fields
  • Stratified random sampling for measuring error rates in high-confidence extractions and detecting novel error patterns
  • Field-level confidence scores calibrated using labeled validation sets for routing review attention
  • The importance of validating accuracy by document type and field segment before automating high-confidence extractions

Skills in:

  • Implementing stratified random sampling of high-confidence extractions for ongoing error rate measurement and novel pattern detection
  • Analyzing accuracy by document type and field to verify consistent performance across all segments before reducing human review
  • Having models output field-level confidence scores, then calibrating review thresholds using labeled validation sets
  • Routing extractions with low model confidence or ambiguous/contradictory source documents to human review, prioritizing limited reviewer capacity
本題情境 · SCENARIO 6
Scenario 6 — Structured Data Extraction（結構化資料抽取）

用 Claude 從非結構化文件(發票、合約、表單)以 extract_invoice 等工具 + JSON schema 抽資訊,維持高準確度。本 Task 教的就是:別被「整體 97% 準確率」騙了——要按文件類型/欄位分層檢查,讓 model 輸出欄位級信心分數、用標註驗證集校準門檻,把低信心或來源矛盾的抽取送人工複核。

一句話抓住主軸:「整體 97% 準確率」會掩蓋某些文件類型或欄位的爛表現。要分層抽樣、按文件類型與欄位拆開看,讓 model 輸出欄位級信心分數並用標註集校準,再把低信心與來源矛盾的抽取優先送人工複核。

Knowledge of · 知識點

知識 1  整體準確率(如 97%)會掩蓋特定文件類型或欄位的爛表現

遇到這個問題時用到系統整體準確率達 97% 而開啟全自動化抽取，但隨後發現手寫表單的「到期日」欄位準確率只有 70%，每天產生數百筆錯誤記錄，卻在整體指標中被高量的電子發票成功案例所掩蓋。

最危險的陷阱:看到「整體 97%」就放心自動化。但這個平均可能藏著:發票抽得很準(99%)、但手寫表單只有 70%;或「金額」欄很準、但「到期日」欄常錯。平均把局部的災難稀釋掉了。自動化前必須拆開看。

# ❌ 只看整體就決定全自動化
if overall_accuracy >= 0.97:
    enable_full_automation()      # 手寫表單 70% 的災難被藏住

# ✅ 整體高,但要往下拆:哪個文件類型/欄位拖後腿?
# invoice: 0.99 | contract: 0.96 | handwritten_form: 0.70 ← 危險
# field due_date: 0.81 ← 危險
考點重點:整體準確率是平均,會掩蓋特定文件類型/欄位的低表現。自動化前要拆開驗。

知識 2  分層隨機抽樣:量測高 confidence calibration（信心校準）抽取的錯誤率、偵測新型錯誤

遇到這個問題時用到系統在一個月內開始出現新型供應商發票格式的抽取錯誤率上升，但因為這類文件在總量中佔比很小，整體指標沒有觸發警報；若有分層抽樣機制，這個新格式的問題可以在早期被偵測到。

就算抽取被標為「高信心」,也不能完全不查。用分層隨機抽樣(按文件類型/欄位分層,各層隨機抽幾筆)持續量測高信心抽取的真實錯誤率,並偵測新型錯誤模式(例如新格式的供應商發票開始出錯)。分層的重點是:每一層都被抽到,不會因為樣本都集中在某類而漏看其他類。

def stratified_sample(extractions, per_stratum=30):
    # 按 (文件類型) 分層,每層隨機抽 N 筆送人工標真值比對
    strata = group_by(extractions, key="doc_type")
    return {dt: random_sample(items, per_stratum)
            for dt, items in strata.items()}
# 每個文件類型都被抽到 → 才抓得到某類別新冒出的錯誤
重點:分層隨機抽樣 → 每層都覆蓋,持續量錯誤率 + 抓新型錯誤,不被高信心標籤蒙蔽。

知識 3  欄位級 confidence calibration（信心校準）分數,用標註驗證集校準,以分配 human review（人工審查）注意力

遇到這個問題時用到系統以整份文件的信心分數路由複核，導致金額欄位信心低（實際準確）與合約條款信心高（實際常錯）的情況被錯誤路由，需要欄位級的信心分數才能準確分配複核資源。

信心分數要做到欄位級(每個抽出欄位各一個分數),而不是整份文件一個分數。而且這個分數要用標註驗證集校準——所謂校準是指:「模型說 0.9 信心」的那批,實際正確率真的接近 90%。校準好的分數才能可靠地拿來路由複核注意力(分數低的優先給人看)。

# 用標註驗證集檢查校準:宣稱 0.9 的那桶,實際正確率是?
def check_calibration(predictions, labels):
    bucket = [p for p in predictions if 0.85 <= p.confidence < 0.95]
    actual = accuracy(bucket, labels)
    # 校準良好: actual ≈ 0.90;若 actual=0.72 → 信心被高估,需重校
    return actual
重點:欄位級信心 + 用標註集校準(0.9 那批實際也要 ≈90%)→ 才能可靠路由複核。

知識 4  自動化高信心抽取前,先按文件類型與欄位區段驗證準確度

遇到這個問題時用到財務部門要求將抽取系統擴展到涵蓋手寫採購單，在驗證階段若沒有按文件類型 × 欄位區段逐格驗證，可能直接將表現不佳的子集納入自動化，造成財務數字系統性錯誤。

承知識 1:在「減少人工複核 / 開啟高信心自動化」之前,必須先確認每一個文件類型、每一個欄位區段的準確度都達標。只要有一個區段不及格(例如手寫表單的金額欄),那個區段就不能納入自動化,要保留人工複核。

def can_automate(segment_accuracy, threshold=0.97):
    # 逐 (doc_type, field) 區段檢查,全部達標才自動化
    unsafe = {seg: acc for seg, acc in segment_accuracy.items()
              if acc < threshold}
    if unsafe:
        return f"以下區段不能自動化,保留人工複核: {unsafe}"
    return "全區段達標,可自動化"
重點:自動化前逐「文件類型 × 欄位」驗證；任一區段不達標就保留人工複核。

Skills in · 技能點

技能 1  對高信心抽取做分層隨機抽樣,持續量錯誤率、偵測新模式

遇到這個問題時用到抽取系統上線後沒有持續監控，三個月後才發現一種新格式的合約文件抽取錯誤率持續偏高；若有每日分層抽樣 QA 管線，這個問題在第一週就應該被偵測到並觸發告警。

知識 2 的實作。建立一條持續的分層抽樣管線:即使抽取已標高信心,仍按層抽樣送人工比對真值,長期監看錯誤率與新冒出的錯誤型態。

def ongoing_qa(daily_extractions):
    sample = stratified_sample(daily_extractions, per_stratum=30)
    labeled = send_to_human_label(sample)
    error_rate = measure_errors(sample, labeled)
    alert_if_drift(error_rate)          # ✅ 新型錯誤上升即告警
    return error_rate
重點:持續性分層抽樣 QA：量錯誤率 + 抓 drift/新型錯誤。

技能 2  按文件類型與欄位分析準確度,確認各區段一致後才減少 human review（人工審查）

遇到這個問題時用到管理層要求在整體準確率達 97% 後立即將人工複核比例從 100% 降至 20%，工程師需要先用 (doc_type × field) 分層準確度分析來說明某些區段還未達標，不能全面降低複核比例。

知識 1/4 的實作。在減少人工複核之前,把準確度按文件類型 × 欄位拆開算,確認每個區段都穩定達標,而不是只看總平均。

def accuracy_by_segment(results):
    table = {}
    for r in results:
        key = (r["doc_type"], r["field"])
        table.setdefault(key, []).append(r["correct"])
    # ✅ 每個 (doc_type, field) 各算一個準確度,逐格檢查
    return {k: mean(v) for k, v in table.items()}
重點:按 (文件類型 × 欄位) 拆算準確度,各區段一致達標才放手減人工。

技能 3  讓 model 輸出欄位級信心分數,用標註驗證集校準複核門檻

遇到這個問題時用到抽取系統以 0.8 作為全域複核門檻，但實際上模型宣稱 0.8 的那批發票，「到期日」欄位的真實準確率只有 72%，需要用標註驗證集重新校準各欄位的門檻，確保高信心標籤與實際準確率相符。

知識 3 的實作。在抽取的 JSON schema 裡讓每個欄位都帶一個 confidence,再用標註驗證集找出一個能可靠分流的複核門檻(例如校準後 < 0.92 才送人工)。

# extract_invoice 的 schema 要求每欄位附 confidence
result = extract_invoice(doc, schema={
    "total":   {"value": ..., "confidence": ...},
    "due_date":{"value": ..., "confidence": ...},
})

# 用標註驗證集找出校準後的複核門檻
THRESHOLD = calibrate_threshold(validation_set, target_precision=0.99)
for field, info in result.items():
    if info["confidence"] < THRESHOLD:
        route_to_human(field)       # ✅ 低於校準門檻才送人工
重點:欄位級 confidence 寫進 schema；用標註集校準出複核門檻來分流。

技能 4  把「低信心」或「來源矛盾/模糊」的抽取送 human review（人工審查）,優先分配有限的複核量能

遇到這個問題時用到複核團隊每天只能審查 500 份文件，但系統每天產生 5,000 份抽取結果，需要一個智慧路由機制，把有限的人力集中在真正有風險的案件（低信心 + 來源矛盾）上，而非均勻抽樣。

人工複核量能有限,要花在刀口上。兩類最該送人工:(1) model 信心低的;(2) 來源文件本身模糊或自相矛盾的(例如發票上金額與小計對不起來)。其餘高信心又來源清楚的就走自動化,把寶貴的人力集中在真正風險高的那些。

def route_for_review(extraction):
    if extraction.confidence < THRESHOLD:
        return "human"                  # 低信心
    if extraction.source_is_contradictory:
        return "human"                  # 來源矛盾/模糊
    return "auto"   # ✅ 把有限人力留給高風險案
重點:低信心 + 來源矛盾/模糊 → 送人工；其餘自動化,優先分配有限複核量能。

整個 Task 5.5 的記憶骨架

結構化抽取別被整體 97% 騙了——平均會掩蓋某些文件類型/欄位的爛表現,自動化前要按文件類型 × 欄位逐區段驗證。用分層隨機抽樣持續量高信心抽取的真實錯誤率、抓新型錯誤。讓 model 輸出欄位級信心分數,用標註驗證集校準(宣稱 0.9 那批實際也要 ≈90%)出複核門檻。最後把低信心與來源矛盾/模糊的抽取送人工,把有限複核量能用在刀口上。

考試情境題

以下三題模擬正式考試格式，每題一個生產情境，四個選項。先嘗試作答，再展開解析。

Q 1 Scenario 6 · Structured Data Extraction

A document extraction system reports an overall accuracy of 97.3% across all document types and fields. Based on this metric, the engineering team enables full automation and eliminates human review. Three weeks later, finance reports that hundreds of handwritten purchase orders have incorrect "due date" values. A post-mortem analysis reveals handwritten form accuracy was 68% for the due_date field. What is the most likely root cause of the monitoring failure?

  1. The model was not fine-tuned on handwritten documents before deployment
  2. The overall accuracy metric masked poor performance on specific document type and field combinations — the high volume of accurately processed digital invoices diluted the handwritten form errors in the aggregate score
  3. The human review team was understaffed and could not catch all errors during the transition period
  4. The due_date field requires a different prompt template that was not configured for handwritten forms
展開解析

Correct Answer: B

B 正確：整體準確率 97.3% 是一個加權平均值，被高量的電子發票（準確率 99%）所稀釋。手寫表單佔整體量很小，其 68% 的 due_date 準確率對總體指標影響微小，因此問題被「藏起來」了。自動化前應按 (doc_type × field) 逐區段驗證，任一區段不達標就不能納入自動化。

A 錯在哪：fine-tuning 可以改善表現，但問題的根源是「沒有在自動化前按文件類型拆開驗證準確度」，即使有 fine-tuning，這個監控設計問題仍然存在。C 錯在哪：問題發生在全自動化後，已沒有人工複核；且即使有人力，根本問題是監控指標設計不當，讓管理層基於錯誤的信心決策啟用全自動化。D 錯在哪：prompt 模板問題是潛在的技術因素，但題目問的是「監控失敗的根因」，監控失敗的原因是整體準確率指標設計不足以揭露分層問題。

Q 2 Scenario 6 · Structured Data Extraction

An extraction system outputs a confidence score of 0.91 for the "total_amount" field on invoice extractions. The team uses 0.90 as the threshold for routing to automated processing. A labeled validation set of 500 invoices reveals that extractions with model confidence between 0.88 and 0.94 have an actual accuracy of only 74%. What does this indicate, and what is the most effective response?

  1. The validation set is too small to be statistically reliable; collect more labeled data before changing thresholds
  2. The model's confidence scores are poorly calibrated — scores in the 0.88–0.94 bucket do not correspond to 88–94% actual accuracy; recalibrate the review threshold using the labeled validation set to find a score that reliably predicts 97%+ accuracy
  3. Lower the automation threshold from 0.90 to 0.85 to allow more extractions through without human review
  4. The issue is specific to the total_amount field; apply a separate extraction model for amounts to improve confidence score reliability
展開解析

Correct Answer: B

B 正確：這是信心分數未校準（uncalibrated）的典型問題——模型宣稱 0.91 信心，但那一批的實際準確率只有 74%，表示信心被嚴重高估。正確做法是用標註驗證集做 confidence calibration（信心校準），找出在驗證集上實際準確率達 97%+ 的信心分數閾值，用校準後的門檻替換原本隨意設定的 0.90。

A 錯在哪：500 筆對於識別信心校準問題已足夠，且問題非常明顯（74% vs 宣稱 88-94%）；等待更多數據只是拖延解決已確認的問題。C 錯在哪：降低閾值到 0.85 讓更多未達標的抽取通過自動化，完全是反向操作，會讓問題更嚴重。D 錯在哪：換一個欄位專用模型是技術上的過度反應，根本問題是信心分數的校準，不是模型本身的能力問題。

Q 3 Scenario 6 · Structured Data Extraction

A document extraction pipeline processes 8,000 documents per day. The human review team can only review 400 documents daily. The current system routes documents for review using random sampling — 5% of all extractions go to human review regardless of confidence score or document characteristics. Recent audits show that 90% of actual errors occur in just 15% of documents: those with low model confidence or contradictory source values (e.g., subtotal + tax ≠ stated total). What change best addresses the allocation of limited review capacity?

  1. Increase the human review team size to handle a larger random sample of documents
  2. Switch from random sampling to prioritized routing — send extractions with low model confidence or contradictory source documents to human review first, reserving random sampling as a secondary check on high-confidence extractions
  3. Reduce the daily processing volume to match what the human review team can fully verify
  4. Implement a second-pass extraction model that re-processes all documents to reduce error rates before human review
展開解析

Correct Answer: B

B 正確：有限的複核量能應集中在高風險案件上。將低信心抽取和來源矛盾的文件（佔 15% 但含 90% 錯誤）優先路由給人工複核，可以讓相同的 400 份複核量能發現更多實際錯誤。對高信心且來源清楚的文件，用隨機抽樣做持續監控（stratified sampling for QA）即可。

A 錯在哪：增加人力是資源層面的解決方案，但問題根本是路由策略設計不當，即使增加人力，隨機抽樣仍然低效，大量人力會浪費在低風險的高信心案件上。C 錯在哪：降低處理量是業務上不可接受的，且沒有解決核心問題——如何讓有限的複核量能發揮最大價值。D 錯在哪：第二次抽取可能改善部分案件，但增加了系統複雜度和成本，且沒有解決「如何把有限複核量能用在刀口上」的資源分配問題。
