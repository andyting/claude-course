考試情境 Scenarios — 題目的真實情境框架

考試是「情境包著知識點」在問。共有 6 個情境，正式考試會隨機抽出其中 4 個，每一題都掛在某個情境下（例如：「客服 agent 在 12% 情況跳過 get_customer，該如何修正？」）。先熟悉這 6 個情境，答題時的語感會更貼近真實考題。

SCENARIO 1
客服解決 Agent
用 Agent SDK 打造客服 agent，處理退貨、帳務爭議、帳號問題；透過 MCP 工具（get_customer、lookup_order、process_refund、escalate_to_human）接後端。目標 80%+ 首次解決率，並懂得何時轉真人。
主要領域：1 Agentic · 2 Tool/MCP · 5 Context
SCENARIO 2
用 Claude Code 寫程式
團隊以 Claude Code 做產碼、重構、除錯、文件。整合自訂 slash command 與 CLAUDE.md，並判斷何時用 plan mode、何時直接執行。
主要領域：3 Claude Code · 5 Context
SCENARIO 3
多代理研究系統
coordinator 把任務拆給多個 subagent（web 搜尋、文件分析、綜合、產報告），最後輸出有引用來源的完整報告。
主要領域：1 Agentic · 2 Tool/MCP · 5 Context
SCENARIO 4
開發者生產力工具
用 Agent SDK 幫工程師探索陌生 codebase、理解 legacy、產 boilerplate、自動化重複工作。使用內建工具（Read、Write、Bash、Grep、Glob）並整合 MCP server。
主要領域：2 Tool/MCP · 3 Claude Code · 1 Agentic
SCENARIO 5
Claude Code 接 CI/CD
把 Claude Code 接進 CI/CD：自動 code review、產測試、PR 回饋。重點在設計能給出可行動回饋、又能降低 false positive 的 prompt。
主要領域：3 Claude Code · 4 Prompt/結構化輸出
SCENARIO 6
結構化資料抽取
用 Claude 從非結構化文件抽資訊，以 JSON schema 驗證並維持高準確度，妥善處理 edge case 並接下游系統。
主要領域：4 Prompt/結構化輸出 · 5 Context

五大領域與權重 Domains & Weightings

百分比為「計分內容」的佔比，反映各領域題目的密度。Domain 1 最重，建議優先準備。

Domain 1 ｜ Agentic 架構與編排
27%

agentic loop 生命週期（tool_use vs end_turn）、coordinator–subagent 多代理編排、subagent 呼叫與 context 傳遞、強制執行與 handoff、Agent SDK hooks、任務拆解、session 狀態與 fork。

Domain 2 ｜ 工具設計與 MCP 整合
18%

用清楚的描述與邊界設計工具介面、MCP 工具的結構化錯誤回應（isError、可重試與否）、工具在各 agent 間的分配與 tool_choice、把 MCP server 接進 Claude Code、善用內建工具（Read/Write/Edit/Bash/Grep/Glob）。

Domain 3 ｜ Claude Code 設定與工作流
20%

CLAUDE.md 階層與模組化、自訂 slash command、plan mode vs 直接執行、Agent Skills、整合外部工具與團隊工作流配置。

Domain 4 ｜ Prompt 工程與結構化輸出
20%

JSON schema 與 tool_use 強制結構化輸出、few-shot 範例降低 false positive、驗證／重試／回饋迴圈、批次處理策略（Message Batches API）、多實例與多回合審查架構。

Domain 5 ｜ Context 管理與可靠性
15%

長對話中保留關鍵資訊（避免 progressive summarization 流失、處理「lost in the middle」）、escalation 與模糊情況的處理、多代理系統的錯誤傳遞、確定性保證 vs 機率性合規。

考試注意事項 Exam Format & Tips

  • 題型：全部為單選題，每題 1 個正確答案、3 個誘答選項（distractor）。誘答選項常是「知識不完整的人會選的答案」，要看懂為什麼錯。
  • 選「最佳」而非「可行」：多個選項往往都「能動」，要選最有效、最對症下藥的那一個——常見模式是「先做低成本、直接命中根因的修正」。
  • 計分：scaled score 100–1000，通過門檻 720，pass/fail；採等化計分以對齊不同題本難度。
  • 不答 = 答錯，且猜題不扣分：每題都要作答，沒把握也選一個。
  • 重視判斷力而非死背：題目考的是正式環境的架構與取捨判斷，不只是概念記憶；需搭配實作經驗。
  • 抓重點反覆出現的原則：確定性保證（hooks／程式化前置條件）勝過機率性的 prompt 指示、工具描述是工具選擇的關鍵、scoped 工具優於塞一堆工具、結構化錯誤優於 generic「失敗」。
常見陷阱題型範例：當「業務邏輯要求確定性」（例如退款前必須先驗證身分），正解通常是程式化強制（hook／prerequisite gate），而非「加強 system prompt」或「加 few-shot」——因為後者靠機率性遵循，在有金錢後果時不夠可靠。
