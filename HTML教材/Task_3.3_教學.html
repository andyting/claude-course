Task Statement 3.3 — Apply path-specific rules for conditional convention loading

Knowledge of:

  • .claude/rules/ files with YAML frontmatter paths fields containing glob patterns for conditional rule activation
  • How path-scoped rules load only when editing matching files, reducing irrelevant context and token usage
  • The advantage of glob-pattern rules over directory-level CLAUDE.md files for conventions that span multiple directories (e.g., test files spread throughout a codebase)

Skills in:

  • Creating .claude/rules/ files with YAML frontmatter path scoping (e.g., paths: ["terraform/**/*"]) so rules load only when editing matching files
  • Using glob patterns in path-specific rules to apply conventions to files by type regardless of directory location (e.g., **/*.test.tsx for all test files)
  • Choosing path-specific rules over subdirectory CLAUDE.md files when conventions must apply to files spread across the codebase
本題情境 · SCENARIO 2
Scenario 2 — Code Generation with Claude Code

團隊用 Claude Code 寫程式、重構、測試。一個成熟 repo 裡,不同類型的檔案各有慣例:測試檔散落各處、Terraform 檔在 infra 目錄。本 Task 教你用 .claude/rules/ 加 glob,讓「對的慣例」只在「編對的檔」時才載入,省 token 又不混淆。

一句話抓住主軸:path-specific rule = 「只在你編到符合 glob 的檔案時,才載入這條慣例」。它解決的痛點是:慣例該按「檔案類型」走,而不是按「目錄」走——而測試檔、infra 檔往往散落在整個 codebase。

Knowledge of · 知識點

知識 1  .claude/rules/ 用 YAML frontmatter 的 paths(glob)做條件啟用

遇到這個問題時用到你有一份詳細的 React 測試慣例規範，但每次編輯任何 Python 後端檔案時 Claude 也把這份規範載入進來，浪費 token 且讓回應充斥無關的測試建議，你需要讓它只在編輯測試檔時才啟用。

在 .claude/rules/ 放規則檔,每份檔開頭用 YAML frontmatter 寫一個 paths 欄位,裡面放 glob pattern。這個 glob 決定:當你編輯到符合的檔案時,這條規則才會被啟用。沒編到符合的檔,它就靜靜躺著、不佔 context。

# .claude/rules/test-conventions.md
---
paths: ["**/*.test.tsx"]   # 只在編輯測試檔時啟用
---
本專案測試慣例:
- 每個測試用 describe/it 結構
- 一個 it 只測一件事
- 不要在測試裡呼叫真實網路
考點重點:規則放 .claude/rules/,用 frontmatter 的 paths(glob)做條件式啟用。

知識 2  path-scoped 規則只在編到符合檔案時載入 → 省 context / token

遇到這個問題時用到你的 CLAUDE.md 把測試規範、infra 規範、前端規範全部常駐載入，工程師反映每次只改一個小檔 Claude 的回應都很慢而且充滿不相關的建議，你需要把這些規範改為條件載入。

這是 path rule 的核心好處。一般的 CLAUDE.md 是永遠載入;但很多慣例其實只跟某類檔案有關。如果把所有慣例都塞進常駐 context,會浪費 token、也讓不相關的規範干擾判斷。

path-scoped 規則是條件載入:你在編 auth.py 時,測試慣例根本不會被載進來;只有你真的打開 auth.test.tsx 時,測試規則才上場。

# ❌ 全塞進 CLAUDE.md:測試慣例、infra 慣例永遠常駐
# CLAUDE.md:測試要... / Terraform 要... / 前端要...
# → 編任何檔都載一整包,大多無關,浪費 token

# ✅ 拆成 path rule:各自只在相關檔案出現時載入
# .claude/rules/test.md     paths: ["**/*.test.tsx"]
# .claude/rules/infra.md    paths: ["terraform/**/*"]
# → 編 auth.py 時,以上兩條都不載入
一句話記住:條件載入 = 只在相關時出現 → 少無關 context、省 token。

知識 3  glob 規則勝過 directory 級 CLAUDE.md（規則檔）:適合「跨多目錄」的慣例

遇到這個問題時用到你的測試慣例文件需要在整個 monorepo 中對所有 .test.tsx 檔案生效，但這些檔案散落在 10 個不同的 service 目錄裡，用 subdirectory CLAUDE.md 維護成本太高，你需要用 glob 一次涵蓋所有測試檔。

你也可以在子目錄放 CLAUDE.md,但它是綁目錄的——只對「那個資料夾底下」生效。問題是:很多慣例是按檔案類型走,而那類檔案散落在整個 codebase。最典型的就是測試檔——它們跟著各自的模組散在四處,不集中在一個資料夾。

這時用 directory 級 CLAUDE.md 會很痛:你得在每個有測試檔的資料夾各放一份、還要同步維護。glob pattern 一條 **/*.test.tsx 就全包了,不管它在哪個目錄。

# ❌ directory CLAUDE.md:測試檔散在 10 個資料夾
# → 要在 10 個資料夾各放一份 CLAUDE.md,難維護、易不一致

# ✅ 一條 glob 全包,不管檔案在哪個目錄
---
paths: ["**/*.test.tsx"]   # ** = 任意層目錄
---
重點:慣例跟著「檔案類型」而非「目錄」時,glob path rule > directory CLAUDE.md。

Skills in · 技能點

技能 1  建 .claude/rules/ 規則檔（rules file）,用 YAML paths 做 path scoping

遇到這個問題時用到你的 Terraform infra 團隊希望 Claude Code 在修改基礎設施檔案時自動套用命名規範與 tagging 要求，但一般後端工程師改 Python 時不該看到這些規則，你需要建立一個只對 terraform/ 目錄下的檔案生效的規則。

知識 1 的實作。官方範例就是 paths: ["terraform/**/*"]:讓這條 infra 慣例只在編輯 Terraform 目錄底下的檔案時載入。

# .claude/rules/terraform.md
---
paths: ["terraform/**/*"]   # 只在編輯 terraform/ 下的檔時載入
---
基礎設施慣例:
- 所有 resource 命名用 snake_case
- 一律加 tags(team、env)
- state 不可手改,改走 plan/apply

技能 2  用 glob 依「檔案類型」套慣例,無視目錄位置

遇到這個問題時用到你想強制所有 React 測試檔使用 Testing Library 的 query by role 方式，但這些 .test.tsx 檔案散落在 src/auth/、src/cart/、packages/ui/ 等多個目錄，你需要用 glob 一條規則涵蓋所有位置。

官方範例:**/*.test.tsx 抓住所有測試檔,不管它在哪個資料夾。** 代表「任意層目錄」,*.test.tsx 鎖檔名型態。

# .claude/rules/react-tests.md
---
paths: ["**/*.test.tsx"]   # 全 codebase 的 React 測試檔
---
React 測試慣例:
- 用 React Testing Library,query by role
- 避免測 implementation detail
- mock 外部 API,不打真實網路

# 不論測試檔在 src/auth/、src/cart/、packages/ui/ 都會套用
重點:** 跨任意目錄 + *.副檔名 鎖類型 → 一條規則涵蓋散落各處的同類檔。

技能 3  何時選 path rule、何時選 subdirectory CLAUDE.md（規則檔）

遇到這個問題時用到payments service 有自己的安全規範只適用於那個目錄，而所有 .stories.tsx 檔的 Storybook 撰寫慣例則散布在整個 repo，你需要決定這兩種情況分別該用 CLAUDE.md 還是 path rule。

判斷準則很乾脆:慣例的適用範圍是「整個子目錄」(例如某個 service 自己的規矩)→ 放那個目錄的 CLAUDE.md。慣例適用於「散落各處的同類檔」(測試、migration、stories...)→ 用 .claude/rules/ + glob。

# ✅ 慣例綁某個目錄 → subdirectory CLAUDE.md
# services/payments/CLAUDE.md:本 service 專屬規範

# ✅ 慣例綁某種「散落各處」的檔案類型 → path rule
---
paths: ["**/*.test.tsx", "**/*.stories.tsx"]
---
# 測試檔、stories 檔遍布 codebase → 用 glob 一網打盡
重點:範圍=整個目錄 → CLAUDE.md;範圍=跨目錄的某類檔 → path-specific rule。

整個 Task 3.3 的記憶骨架

在 Scenario 2 的 repo 裡,把慣例放進 .claude/rules/,用 YAML frontmatter 的 paths(glob) 做條件式啟用——只在編到符合的檔案時才載入,因此省 context、省 token。當慣例跟著「檔案類型」而非「目錄」走(測試檔散在整個 codebase),用 **/*.test.tsx 這種 glob 勝過在每個資料夾放 CLAUDE.md。一句判斷:綁目錄用 CLAUDE.md,綁散落各處的檔案類型用 path rule。

考試情境題

以下三題模擬正式考試格式，每題一個生產情境，四個選項。先嘗試作答，再展開解析。

Q 1 Scenario 2 · Code Generation with Claude Code

A team notices that whenever any engineer opens a Python backend file, Claude Code loads both the Terraform infrastructure rules and the React testing conventions along with the general coding standards. Developers report wasted tokens and irrelevant suggestions on every interaction. The team wants these specialized rules to load only when relevant files are being edited. What is the most effective approach?

  1. Move the Terraform and React testing rules into the user-level ~/.claude/CLAUDE.md so they are only loaded for engineers who need them.
  2. Create separate files in .claude/rules/ with YAML frontmatter paths fields—paths: ["terraform/**/*"] for Terraform and paths: ["**/*.test.tsx"] for React tests—so each rule loads only when editing matching files.
  3. Create subdirectory CLAUDE.md files in the terraform/ directory and in every directory containing .test.tsx files.
  4. Use @import in the root CLAUDE.md to conditionally import each rule file based on the current working directory.
展開解析

Correct Answer: B

path-specific rule 的核心機制就是在 .claude/rules/ 的檔案裡加 YAML frontmatter 的 paths 欄位，只有當你編輯到符合 glob 的檔案時才載入，完全解決「編 Python 卻載入 Terraform 規則」的問題。

A 錯在哪：移到使用者層只改變了規則對哪些人可見，不能解決「什麼時候載入」的問題，而且讓團隊規範離開版控。C 錯在哪：在每個含測試檔的目錄放 CLAUDE.md 極難維護，而且測試檔散落各處時這種做法需要數十份文件同步。D 錯在哪：@import 是靜態引用機制，CLAUDE.md 裡的 @import 無法根據當前編輯的檔案類型做動態條件載入。

Q 2 Scenario 2 · Code Generation with Claude Code

A team has React test conventions they want Claude Code to apply consistently. Their .test.tsx files are spread across 12 different directories throughout the monorepo. An engineer proposes placing a CLAUDE.md file in each of the 12 directories. A tech lead suggests using a single path-specific rule instead. Which approach is superior and why?

  1. The subdirectory CLAUDE.md approach, because directory-scoped rules take higher precedence than glob-based rules, ensuring the conventions override any conflicting project-level settings.
  2. The single path-specific rule with paths: ["**/*.test.tsx"], because it applies the convention to all test files regardless of directory location with a single maintainable file.
  3. Both approaches are equivalent; the choice depends solely on team preference for file organization.
  4. The subdirectory CLAUDE.md approach, because glob patterns cannot match files in nested directories more than two levels deep.
展開解析

Correct Answer: B

glob 的 ** 代表「任意層目錄」，一條 **/*.test.tsx 就能涵蓋整個 codebase 中所有位置的測試檔，只需維護一份規則，修改時也只需動這一個檔案，比在 12 個目錄各放一份容易得多。

A 錯在哪：path-specific rule 與 subdirectory CLAUDE.md 的優先順序問題不是選擇的關鍵，而且多檔維護的問題才是核心痛點。C 錯在哪：兩者並不等價——單一 glob rule 的維護成本遠低於 12 份 CLAUDE.md，也更不容易因忘記更新某一份而造成不一致。D 錯在哪：** glob 可以匹配任意深度的巢狀目錄，這個說法是錯的。

Q 3 Scenario 2 · Code Generation with Claude Code

An architect is designing the rule structure for a monorepo. The payments service has specific PCI compliance standards that should apply to everything under services/payments/. Additionally, all database migration files (named *.migration.sql and scattered across multiple services) must follow a common migration convention. Which combination of approaches correctly addresses both requirements?

  1. Use a path-specific rule with paths: ["services/payments/**/*"] for PCI compliance, and another path-specific rule with paths: ["**/*.migration.sql"] for migration conventions.
  2. Use a subdirectory CLAUDE.md in services/payments/ for PCI compliance, and a path-specific rule with paths: ["**/*.migration.sql"] for migration conventions.
  3. Use a subdirectory CLAUDE.md in services/payments/ for PCI compliance, and subdirectory CLAUDE.md files in each directory containing migration files.
  4. Use a single root-level CLAUDE.md with both PCI and migration rules, and rely on Claude to apply the relevant section based on context.
展開解析

Correct Answer: B

PCI 規範綁的是整個 payments 目錄，所以 subdirectory CLAUDE.md 是正確工具；migration 慣例綁的是散落各處的特定檔案類型，glob path rule 才是正確工具。兩個需求用不同工具，各司其職。

A 錯在哪：雖然也能運作，但 payments 的 PCI 規範其實是「綁目錄」的情境，subdirectory CLAUDE.md 語意更清晰，glob 適合跨目錄的檔案類型情境。B 才是教材明確建議的最佳分工。C 錯在哪：migration 檔散落各處，在每個目錄放 CLAUDE.md 的維護成本極高，完全是 glob rule 要解決的痛點。D 錯在哪：把所有規範塞進 CLAUDE.md 會讓它常駐載入，失去 path-scoped rule 的條件載入優勢，也難以維護。
