官方考綱原文

Task Statement 5.6 — Preserve information provenance and handle uncertainty in multi-source synthesis

Knowledge of:

  • How source attribution is lost during summarization steps when findings are compressed without preserving claim-source mappings
  • The importance of structured claim-source mappings that the synthesis agent must preserve and merge when combining findings
  • How to handle conflicting statistics from credible sources: annotating conflicts with source attribution rather than arbitrarily selecting one value
  • Temporal data: requiring publication/collection dates in structured outputs to prevent temporal differences from being misinterpreted as contradictions

Skills in:

  • Requiring subagents to output structured claim-source mappings (source URLs, document names, relevant excerpts) that downstream agents preserve through synthesis
  • Structuring reports with explicit sections distinguishing well-established findings from contested ones, preserving original source characterizations and methodological context
  • Completing document analysis with conflicting values included and explicitly annotated, letting the coordinator decide how to reconcile before passing to synthesis
  • Requiring subagents to include publication or data collection dates in structured outputs to enable correct temporal interpretation
  • Rendering different content types appropriately in synthesis outputs—financial data as tables, news as prose, technical findings as structured lists—rather than converting everything to a uniform format
本題情境 · SCENARIO 3
Scenario 3 — Multi-Agent Research System（多代理研究系統）

多代理研究系統的終點是「有引用來源的完整報告」。當 web 搜尋與文件分析 subagent 的發現流經 synthesis subagent,出處最容易在摘要步驟中流失,可信來源間的數據也常打架。本 Task 教的就是:用結構化 claim-source mapping 把「哪句話出自哪裡」一路保到底,並誠實標注衝突與發佈日期。

一句話抓住主軸:多來源綜合時,出處會在摘要步驟流失,可信來源間的數字會打架。對策:用結構化 claim-source mapping 把「哪句話來自哪裡」一路保到 synthesis;遇到衝突要標注雙方來源、不要擅自挑一個;並要求附上發佈日期,免得不同時期的數字被當成矛盾。

Knowledge of · 知識點

知識 1  摘要步驟會弄丟 provenance（來源溯源）——當發現被壓縮卻沒保住 claim-source mapping（主張來源對應）

遇到這個問題時用到研究報告中引用「市場成長 35%」這個數字，但讀者要求查證原始來源時，synthesis 步驟已將出處資訊丟失，整份報告的可信度因為無法追溯引用來源而受到質疑。

多代理研究的常見失血點:web 搜尋 subagent 找到「市場成長 35%」並記得出處,但到了摘要 / 綜合步驟,內容被壓縮,而「這句話對應哪個來源」的映射沒被一起保留。最終報告只剩一個沒有出處的數字,無法被引用或查證。

# ❌ 摘要時只留結論,claim→source 的對應被丟掉
summary = "市場成長 35%,競爭加劇。"
# 35% 出自哪份報告?沒了 → synthesis 無法標引用

# ✅ 壓縮內容時,claim-source mapping 必須一起留著
claim = {
    "claim": "市場 2025 成長 35%",
    "source_url": "https://example.com/r",
    "document_name": "2025 市場報告",
}
考點重點:出處在摘要步驟流失,因為「claim→source 映射」沒跟著被保留。

知識 2  結構化 claim-source mapping（主張來源對應）:synthesis 必須保留並合併

遇到這個問題時用到Synthesis subagent 將三個 subagent 的發現合併成一段散文時，將每個主張對應的來源全部混合丟失，最終報告無法標明哪句話來自哪份文件，無法通過法律部門的引用審查。

解法是讓每個發現都帶結構化的 claim-source mapping(主張 ↔ 來源)。重點在 synthesis subagent 的職責:它在合併多個 subagent 的發現時,必須保留每筆 mapping,而不是把它們攪成一段沒有出處的散文。合併後,每個主張仍能追回原始來源。

def synthesis_merge(search_findings, doc_findings):
    # ✅ 合併時保留每一筆 claim-source mapping,不攪糊
    merged = []
    for f in search_findings + doc_findings:
        merged.append({
            "claim": f["claim"],
            "source": f["source"],     # 出處一路保到底
            "excerpt": f["excerpt"],
        })
    return merged   # 每個主張都還能追回來源
重點:synthesis 合併發現時,必須保留並合併 claim-source mapping,出處不能斷。

知識 3  可信來源間數據 conflict annotation（衝突標注）+ 雙方出處,而非任意挑一個

遇到這個問題時用到A 報告（IEA）與 B 報告（BloombergNEF）對同一市場成長率給出 35% 和 28% 的不同數字，synthesis agent 若擅自選擇其中一個，讀者無法知道另一個可信來源的存在，可能做出基於單一視角的錯誤決策。

當兩個都可信的來源給出不同數字(A 報告說成長 35%、B 報告說 28%),不可以擅自挑一個寫進報告、把另一個丟掉。正確做法是把衝突標注出來,並附上各自的出處,讓讀者(或下游)知道有分歧、各自從何而來。

# ❌ 任意挑一個,另一個悄悄消失
growth = "35%"   # B 報告的 28% 被無聲丟棄

# ✅ 標注衝突,各自附出處
growth = {
    "conflict": True,
    "values": [
        {"value": "35%", "source": "A 報告"},
        {"value": "28%", "source": "B 報告"},
    ],
}
重點:可信來源衝突 → 標注分歧 + 雙方出處,絕不任意選一個值。

知識 4  時間性資料:要求附發佈/採集日期,避免時間差被誤判為 conflict annotation（衝突標注）

遇到這個問題時用到Synthesis agent 將 2024 Q4 的失業率 4.1% 與 2025 Q3 的 3.8% 標記為「數據衝突」，但這兩個數字都正確，只是時間點不同；若結構化輸出強制附上採集日期，就不會發生這種誤判。

有些「衝突」其實只是時間不同:A 說失業率 4.1%(2024 資料)、B 說 3.8%(2025 資料)——它們不矛盾,只是不同時點。若結構化輸出不帶日期,下游會把時間差誤判成矛盾。所以要求每筆數據都附發佈或採集日期。

# ✅ 每筆數據附日期,時間差不會被當成矛盾
stat = {
    "metric": "失業率",
    "value": "4.1%",
    "collection_date": "2024-Q4",   # ← 關鍵:標時點
    "source": "勞動統計局",
}
# 下游看到 2024 vs 2025,知道是時序變化而非衝突
重點:結構化輸出要附發佈/採集日期,免得不同時期的數字被誤讀為矛盾。

Skills in · 技能點

技能 1  要求 subagent 輸出結構化 claim-source mapping（主張來源對應）,讓下游一路保留 provenance（來源溯源）

遇到這個問題時用到Web 搜尋 subagent 找到了關鍵的再生能源投資成長數字，但輸出規格只要求 claim 文字，沒有強制附上 source URL 和原文 excerpt，導致下游 synthesis 在引用時缺乏可追溯的出處。

知識 1/2 的實作。在 subagent 的輸出規格裡強制每筆發現帶上 source URL、文件名、相關摘錄(excerpt),且要求下游 synthesis 原樣保留到最終報告。

# web 搜尋 subagent 的輸出規格
finding = {
    "claim": "再生能源 2025 投資成長 22%",
    "source_url": "https://iea.org/report-2025",
    "document_name": "IEA World Energy Investment 2025",
    "excerpt": "Global renewable investment rose 22% ...",
}
# ✅ synthesis 必須把這四個欄位一路保留到報告引用區
重點:subagent 輸出強制帶 URL/文件名/excerpt；下游綜合原樣保留。

技能 2  報告分區:明確區分「已確立」與「有爭議」的發現,保留原始來源定性

遇到這個問題時用到研究報告將「市場規模超過 500 億（3 個獨立來源確認）」與「年成長率 28-35%（兩份報告數字不同）」並排呈現，讀者無法分辨哪些是共識結論、哪些是仍有爭議的數字，需要明確的分區設計。

知識 3 的實作。把最終報告用明確區塊切開:一塊放已充分確立的發現,一塊放仍有爭議的發現;並保留各來源原本的定性描述與方法論脈絡(例如「該數字為估計值,樣本 n=200」),不要抹平成斬釘截鐵的結論。

report = {
    "well_established": [
        {"claim": "市場規模逾 500 億美元", "sources": ["A", "B", "C"]},
    ],
    "contested": [
        {"claim": "年成長率",
         "positions": [{"value": "35%", "source": "A(估計)"},
                       {"value": "28%", "source": "B(實測 n=200)"}]},
    ],   # ✅ 保留原始定性與方法論
}
重點:報告分「已確立 / 有爭議」兩區,保留原始來源定性與方法論脈絡。

技能 3  文件分析帶著 conflict annotation（衝突標注）交出,由 coordinator 決定如何調和

遇到這個問題時用到文件分析 subagent 發現同一份文件內市占率數字前後不一致，若 subagent 自行選擇一個值上報，coordinator 和最終讀者都不會知道文件本身就有矛盾，而此矛盾本身可能是重要的發現。

知識 3 的職責劃分。文件分析 subagent 不該自己解決衝突。它的工作是把衝突值連同標注一起完整交出,把「要怎麼調和」的決定權留給 coordinator——coordinator 有全局視野,再決定傳給 synthesis 前如何處理。

def analysis_subagent(doc):
    values = extract_metric(doc, "市占率")
    if len(set(values)) > 1:
        # ✅ 不自行決定,標注衝突原樣上交給 coordinator
        return {"status": "ok", "conflict": True,
                "values": values,
                "note": "文件內市占率數字不一致,待調和"}
    return {"status": "ok", "value": values[0]}
# coordinator 收到後再決定如何調和,才傳給 synthesis
重點:analysis subagent 把衝突明確標注後上交,調和決策交給 coordinator。

技能 4  要求 subagent 在結構化輸出附上發佈/採集日期

遇到這個問題時用到Subagent 輸出格式沒有強制包含 publication_date 欄位，coordinator 收到兩筆失業率數字（4.1% 和 3.8%）時無法判斷是時序變化還是真正的數據矛盾，需要將日期設為必填欄位並在缺失時拒絕接受輸出。

知識 4 的實作。把「附日期」寫進 subagent 輸出的硬性規格:每筆數據都要有 publication date 或 data collection date,讓 synthesis 能正確做時序判讀,而非把不同年份的數字當成打架。

OUTPUT_SCHEMA = {
    "claim": "str",
    "value": "str",
    "source": "str",
    "publication_date": "required",   # ✅ 必填,缺則退回
}
def validate_finding(f):
    if not f.get("publication_date"):
        raise ValueError("缺發佈日期,無法正確時序判讀")
重點:把「附發佈/採集日期」設為輸出硬性必填,支援正確時序判讀。

技能 5  不同內容類型用適當形式呈現,別全部塞成同一種格式

遇到這個問題時用到Synthesis agent 將財務數據、新聞摘要和技術規格全部轉成散文格式，導致財務數字難以比較、技術規格難以查找；需要根據內容類型選擇最適合的呈現形式（表格、散文、清單）。

synthesis 輸出要因內容而異:財務數據用表格、新聞用散文、技術發現用結構化清單。把所有東西硬轉成同一種格式(例如全部寫成散文)會讓財務數字難讀、技術細節難查。讓形式服務內容。

def render_section(content_type, data):
    if content_type == "financial":
        return to_table(data)            # 財務 → 表格
    if content_type == "news":
        return to_prose(data)            # 新聞 → 散文
    if content_type == "technical":
        return to_bullet_list(data)      # 技術 → 結構化清單
    # ✅ 形式服務內容,不全轉成單一格式
重點:財務→表格、新聞→散文、技術→清單;別把所有內容壓成同一格式。

整個 Task 5.6 的記憶骨架

多代理研究的終點是有引用來源的報告,但出處最容易在摘要步驟流失。對策:每筆發現帶結構化 claim-source mapping(URL/文件名/excerpt),synthesis 合併時原樣保留。可信來源數據衝突時要標注雙方出處、不擅自挑值,且把調和決定權留給 coordinator;數據一律附發佈/採集日期,避免時間差被誤判為矛盾。報告分已確立 / 有爭議兩區、保留原始定性,並讓財務用表格、新聞用散文、技術用清單,形式服務內容。

考試情境題

以下三題模擬正式考試格式，每題一個生產情境，四個選項。先嘗試作答，再展開解析。

Q 1 Scenario 3 · Multi-Agent Research System

A multi-agent research system produces a report on renewable energy investment trends. The web search subagent finds the claim "Global renewable investment rose 22% in 2025" with a source URL from IEA. The synthesis subagent merges findings from three subagents into a final report. The final report states "Renewable investment grew significantly in 2025" with no source citation. A client challenges the figure and the team cannot locate the original source. What is the most likely root cause?

  1. The web search subagent did not verify the IEA figure before including it in its output
  2. The synthesis subagent merged findings without preserving the claim-source mappings from subagent outputs, losing the source URL and excerpt during the summarization step
  3. The IEA source URL was invalid and could not be accessed by the synthesis subagent
  4. The coordinator did not instruct the synthesis subagent to include citations in the final report
展開解析

Correct Answer: B

B 正確：這是「摘要步驟弄丟 provenance（來源溯源）」的典型案例。Web 搜尋 subagent 確實有來源資訊（IEA URL + excerpt），但 synthesis subagent 在合併多個 subagent 的發現時，只保留了結論文字而丟棄了 claim-source mapping，導致最終報告無法追溯引用來源。正確做法是讓 synthesis 在合併時原樣保留每筆 claim-source 對應。

A 錯在哪：問題不在來源的真實性，而在出處資訊在 synthesis 步驟中被丟失。即使 IEA 數字完全正確，沒有保留引用來源的報告仍無法通過引用審查。C 錯在哪：問題發生在 synthesis 合併步驟，與 URL 是否可訪問無關；且 synthesis 應使用 subagent 已提供的 excerpt，不需要重新訪問原始 URL。D 錯在哪：coordinator 的指示是次要因素，根本問題是 synthesis 的資料流設計沒有保留 claim-source mapping；即使有明確指示，若 synthesis 接收到的輸入已丟失出處資訊，它也無法重建。

Q 2 Scenario 3 · Multi-Agent Research System

A research system is synthesizing data on electric vehicle market share. Source A (industry report, 2024-Q4) states 18% EV market share. Source B (government statistics, 2025-Q3) states 23% market share. The synthesis subagent flags this as a "data conflict" and requests coordinator intervention to resolve which number to use. A senior analyst reviewing the system notes this behavior is incorrect. What is the most effective change to address this?

  1. Configure the synthesis subagent to always select the more recent source when values conflict
  2. Require subagents to include publication or data collection dates in structured outputs so the synthesis agent can recognize temporal differences as sequential data points rather than conflicts
  3. Add a data validation step that rejects any source with values differing by more than 10 percentage points
  4. Have the synthesis subagent average conflicting values to produce a single consensus figure
展開解析

Correct Answer: B

B 正確：18%（2024-Q4）和 23%（2025-Q3）不是衝突，而是時序資料的正常變化——EV 市占率在一年內從 18% 成長到 23%。若每筆數據都附上採集日期，synthesis agent 就能正確判讀這是時序變化，而非需要調和的矛盾。這正是「附發佈/採集日期避免時間差被誤判為矛盾」的核心應用。

A 錯在哪：「永遠選最新來源」的啟發法會丟失時序趨勢資訊，且在真正存在方法論差異的衝突中（而非只是時間差）也可能選錯。問題根源是無法區分「時間差」和「真正的數據矛盾」，而不是選哪個數字。C 錯在哪：以差距超過 10% 為標準拒絕來源是任意的閾值，且在動態市場中不同時間點的數字差距可能合理超過這個範圍，這個規則會過度拒絕有效資料。D 錯在哪：對 18% 和 23% 取平均值（20.5%）得到一個在任何時間點都不準確的數字，且會破壞時序趨勢資訊，是最不應該做的處理方式。

Q 3 Scenario 3 · Multi-Agent Research System

A document analysis subagent is processing a market research document. It extracts the "market share" metric and finds two different values within the same document: 34% on page 2 (in an executive summary) and 31% on page 8 (in a detailed methodology section with a note that the figure excludes one geographic region). The subagent selects 34% as the "primary" value and returns only that in its structured output. A downstream coordinator later challenges the figure. What change best addresses this issue?

  1. Instruct the subagent to always prefer the value that appears first in the document
  2. Have the subagent complete analysis with conflicting values explicitly annotated — including both values and a note explaining the discrepancy — and pass this to the coordinator to decide how to reconcile before synthesis
  3. Have the subagent automatically select the lower value to ensure conservative estimates
  4. Add a post-processing validation step that checks all extracted values against an external benchmark database
展開解析

Correct Answer: B

B 正確：文件分析 subagent 不應自行解決文件內的衝突——它沒有全局視野來決定哪個值更適合最終報告的目的。正確做法是把衝突值連同明確的 conflict annotation（衝突標注）和差異說明完整上交給 coordinator，讓有全局視野的 coordinator 決定如何調和（例如：用於全球市場分析時用 34%，用於區域比較時需澄清 31% 的地理排除範圍）。

A 錯在哪：「優先選第一個出現的值」是任意啟發法，且在此案例中選擇了缺乏方法論細節的執行摘要數字（34%），而忽略了有更完整脈絡的方法論說明（31%）；這種做法系統性地偏向較草率的數字。C 錯在哪：永遠選較低值的保守策略會在某些分析場景中產生錯誤結論（如競爭對手市占率分析需要準確值而非保守值），且忽略了兩個值背後不同的方法論意義。D 錯在哪：外部基準資料庫無法解決「同一文件內兩個不同口徑的數字」這種文件內部衝突問題，且增加了不必要的系統複雜度。
